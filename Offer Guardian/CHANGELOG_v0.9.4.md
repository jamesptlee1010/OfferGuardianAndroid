# Offer Guardian v0.9.4 — History Filters (built on v0.9.3)

## New controls

- History screen: **Filters** beside **Today / Last 7 days / Last 30 days / All dates**.
- Minimum **and** maximum bounds for **offer payment**, **estimated routed hourly rate**, **payment per km**, and **distance**.
- ALL (AND) vs ANY (OR) between metric ranges; a min/max pair on the same metric is always an inclusive range.
- Input validation: non-negative numbers, inclusive minimum <= maximum, maximum 2 decimals in currency and 3 decimals in distance; invalid input cannot silently overwrite existing filters.
- Filters persist across History screen sessions. **Clear all** resets only history filters.
- List, matching counts and all summary statistics use the same database predicate, along with the date range, search text and selected tab.
- Unknown/unverified rates excluded from hourly and per-kilometre conditions. For OR mode, an unverified row can still qualify solely through a known payout condition. Rate shown as **Unknown**, never zero.
- Monetary threshold comparisons use *exact integer cents*; rate thresholds are evaluated by cross multiplication against the **original total minutes** or **metres** (without rounding displayed values).
- Original CSV export remains **all offers** and is labelled accordingly, ensuring that filters never cause a partial backup.

## Preserved

- v0.9.3 verified OCR duration/payout safeguards and local SQLite migration.
- v0.9.1 Faster Waze/day-night offer detection, existing rule builder, alarms, and optional declines.
- On-device database schema version 2; no data migration required on upgrade.

## Verification and limitations

- `OfferHistoryFiltersStandaloneTest`: 45 standalone Java assertions.
- `test_history_filters_sql.py`: 9 queries actually executed against temporary SQLite rows generated by production Java filter builder.
- Original project host-side regression suites still available in GitHub Actions.
- Android SDK/Gradle and live Uber/Waze device tests are unavailable in this environment. The GitHub workflow includes `assembleDebug` to compile the APK.
- This update deliberately **does not** modify the OCR retry/auto-decline behaviour for over-hour offers. That is a separate fix discussed earlier.
