# v2.4.0 — DoorDash stability

Based on v2.3.0. Same application ID, settings and history database. Source only; Android APK build/device verification pending.

- Accessibility-first DoorDash reading; crop OCR to offer/confirmation panel and top notification/decline region as fallback. Retain Uber visual detector for competing offers. Try the pending confirmation directly from visible accessibility text without another screenshot when available.
- Maintain two matching reads before stage 1. After verified stage 1, one fresh identifiable confirmation is sufficient, with the original pending decline, live DoorDash window ownership, unchanged failing rules and countdown/deadline checks. If countdown is unreadable, require same window and a recent pending action. At most one verified retry per step if original offer/dialog is still visible. Never blind tap or accept.
- Permit informational qualifying overlay when the rate is readable but decline control/timer is missing. Display on upper-right below DoorDash's native Decline. Still apply actual configured rules; no automatic change to AND/OR, enabled conditions or thresholds. Save most recent rule explanation, raw parsed payout/metrics and order count for troubleshooting. Separate DoorDash rules selected but not saved now results in manual review, rather than silent shared-rule fallback.
- Recognize explicit Drop off 2 orders (and analogous 3-order wording, not yet observed live) with compatible stop count. Ambiguous counts remain manual review.
- Notification listener matches package-verified New Delivery! in standard Android extras, retains a short-lived trigger, and logs matches. No requirement for exact Uber idle wording before switching. Known active deliveries, competing actions, disabled settings, stale notification and visible competing Uber offer still block switching. Background activity restrictions may still prevent launching; verify foreground and report failure. Other-app switching is enabled by default only if no existing preference is saved; respect existing choices. No notification content archived.
- Preserve D | DF | DR | U, draggable pill, Uber logic, history, alerts and opt-in real declines. Verify actual delivery state on the device; detection of known active delivery is not exhaustive. Keep disabled during active jobs and test only while parked. Check delivery platform terms before enabling automation.
