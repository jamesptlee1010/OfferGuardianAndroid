# Offer Guardian 2.6.1 — Stability and history

Base: v2.6.0, app ID and database unchanged, versionCode 32.

- DoorDash stage 1 now locks its original verified financial decision, window and countdown deadline against routine OCR identity resets. Stage 2 only permits a new session after independently agreeing new financial evidence or recognised idle. An exact accessible confirmation is checked ahead of routine scanning, even while an obsolete capture is outstanding; window, current rules, deadline, unobstructed target and test-mode checks remain mandatory. Watchdog recovery and missing gesture callbacks no longer automatically erase an unexpired stage-1 session. Unarmed/expired confirmations remain untouched.
- Uber retry cooldown 1.5 seconds rather than 550 ms; verified click remains preferred; touchscreen holds 90/140/200 ms across up to three attempts. A completed gesture is not an independently confirmed decline. Existing cross-app visual fallback retained.
- Context-bound OCR normalization for isolated `l`, `I`, `|` in numeric time slots, including `l hrl min`; original text retained. Repeated payout OCR failures alternate contrast-enhanced and bounded 1.25x enlarged card crops with coordinate remapping. Ambiguous or clipped amounts are not guessed. Two-frame financial verification remains.
- Monitoring selector: Uber only, DoorDash only, both or neither. Uber-only avoids DoorDash offer/notification processing and hides D/DF/DR dock; Uber overlays over DoorDash can still be recognized. DoorDash-only bypasses Uber pixel matcher and releases its reusable buffers; no Uber actions. Mode changes invalidate stale captures and clear transient sessions; existing rules/history remain. Notification access remains a user-granted Android permission.
- Reuse normalized Uber pixel array (~4 MB allocation avoided per capture), explicitly recycle temporary bitmaps, cap outstanding OCR tasks at two; if both fail to complete scanning pauses and logs backlog. Watchdog evidence invalidation retained; no confirmed fix for all device stalls.
- Full verified history rows are checked for matching offer type, cents, minutes, metres, count, destination and similar pickup within 60 seconds. Punctuation/spacing OCR variants are tolerated; no fuzzy action authorization. Recent alert suppression uses financial key plus destination. If two genuinely separate otherwise identical offers recur within 60 seconds they may be coalesced/suppressed; no platform offer ID is exposed. Incomplete records may still duplicate.
- History > Scan for duplicate offers: preview candidate groups, select manually or select all, confirm deletion. Only complete verified metrics and matching destinations/near-identical pickup within 60 seconds, groups with more than one confirmed outcome excluded. Revalidates previewed rows in a SQLite transaction and retains the strongest single outcome/action and earliest time. Existing stats refresh from remaining rows. Export CSV before cleanup.
- $30/hr defaults for each delivery tier and both platforms retained. Existing saved rules, dual-platform overlays, history import/export and vertical controls retained.

Host regression and Java syntax checks passed; full Android compilation, SQLite integration on device, actual OCR, memory usage and gesture success are unverified here. Test safely parked with test-only toggles first.
